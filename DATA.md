# Сторонние данные и код: что здесь не хранится и почему

Репозиторий не редистрибутирует ни один крупный сторонний файл. У каждого есть
канонический источник и контрольная сумма; воспроизведение — двумя скриптами из
`scripts/`. Причины три: лицензионная чистота (см. ниже), размер и то, что копия
без DOI хуже ссылки с DOI.

## 1. Коннектом FlyWire и модель Shiu et al.

| | |
|---|---|
| Источник | `https://github.com/philshiu/Drosophila_brain_model` |
| Зафиксированный коммит | `91bdd1e7dcf193f3e7ca5a8933497fcef63b7960` (2024-09-14) |
| Размер | ~370 МБ вместе с историей git |
| Лицензия кода | MIT, © 2023 Philip Shiu and Nico Spiller |
| Лицензия данных внутри | **CC BY-NC 4.0** (FlyWire), отдельно от MIT |

Данные коннектома лежат **внутри** этого репозитория (`2023_03_23_connectivity_630_final.parquet`,
86 МБ для v630 и 100 МБ для v783), вопреки его Readme, который предлагает скачивать
внешний архив. Скачивать ничего дополнительно не нужно.

Клонировать: `python scripts/setup_model.py` (клонирует на зафиксированный коммит).

**Почему не вендорим.** Если бы код и данные форка лежали здесь, репозиторий
редистрибутировал бы данные под CC BY-NC 4.0, и ограничение NC распространилось бы
на весь репозиторий. Оставляя форк снаружи, мы держим лицензию своего кода
независимой от NC. Это же соображение — в записке «Организационная форма и лицензии
стенда», раздел 2.

Форк используется **без правок кода**: `git status` в клоне чист. Это проверено и
является доводом раздела 5.6 whitepaper.

## 2. Данные вольтажной регистрации, Huang et al. 2024

| | |
|---|---|
| Источник | Zenodo, DOI `10.5281/zenodo.10998457` |
| Лицензия | **CC BY 4.0** — ограничения NC нет |
| Размер | 920 МБ, пять архивов |
| Используются | `Figure3.zip` и `Figure4.zip` (эталон), `Figure1.zip` и `Figure2.zip` (проверка формата и калибровка) |

Скачать и проверить: `python scripts/fetch_huang_data.py`.

Контрольные суммы SHA-256 — `results/huang_reference/checksums.txt`; скрипт сверяет
с ними и отказывается принимать файл с расхождением.

**Замечание по скачиванию.** Файловый эндпоинт Zenodo регулярно отвечает 504 при
работающих метаданных. Скрипт качает во временный файл, сверяет точный размер из
API и только потом переименовывает; докачка через `curl -C -` для этого источника
непригодна — на 504 в файл пишется HTML-страница ошибки, и продолжение дописывает
данные поверх неё.

## 3. Разметка типов клеток FlyWire v630 и метаданные hemibrain

| | |
|---|---|
| Источник | `https://github.com/flyconnectome/flywire_annotations`, тег `v1.1.0`, коммит `df6bb136f5b3d91c3992df4e8de2642329e2a384` |
| Файлы | `Supplemental_file1_annotations.tsv` (21,7 МБ), `Supplemental_file4_hemibrain_meta.csv` (2,4 МБ) |
| Лицензия аннотаций FlyWire | **CC BY-NC 4.0** (в репозитории-источнике файла `LICENSE` нет; относим к условиям FlyWire [27], как остальные данные коннектома) |
| Лицензия метаданных hemibrain | CC BY 4.0 (наше прочтение условий Janelia; в самом файле лицензия не объявлена) |

Скачать и проверить: `python scripts/fetch_flywire_annotations.py`.
Контрольные суммы SHA-256 — `results/mb_subcircuit/checksums.txt`.

**Почему тег `v1.1.0`, а не `main`.** Начиная с релиза `v2.0.0` поле `root_id`
в этих файлах относится к материализации FlyWire **783**, а модель [2] построена
на **630**; идентификаторы разных материализаций не совпадают, и смешивать их
нельзя. `v1.1.0` — последний релиз, где `root_id` относится к 630. Оговорка:
это версия аннотаций из препринта Schlegel et al.; версия, на которую ссылается
статья в *Nature* [18], — тег `v2.1.0` на 783. Сопоставить 783 с 630 можно было
бы через `supervoxel_id` и CAVE, но это требует токена доступа и вносит ещё один
непроверяемый шаг, поэтому не делается.

**Почему не Codex.** `codex.flywire.ai/api/download` отдаёт страницу входа:
выгрузка аннотаций там за авторизацией. Репозиторий [18] открыт и, в отличие от
Codex, содержит согласованный и сверенный набор — на что указывает и README
самого репозитория.

**Метаданные hemibrain — зачем.** FlyWire не размечает компартменты грибовидного
тела. В метаданных hemibrain [9] компартмент стоит в поле `instance`
(`MBON11(y1pedc>a/B)_R`), и карта «тип → компартмент» строится оттуда
скриптом `build_mb_subcircuit.py`. Сама карта (63 строки) идёт в git как
`results/mb_subcircuit/compartment_map.tsv`: это номенклатура типов из [9] под
CC BY 4.0, а не выгрузка данных FlyWire.

**Что из подсхемы не идёт в git.** `data/mb_subcircuit/` целиком: список ID с
типами (`neurons.csv`) и подсхема в формате модели (`completeness.csv`,
`connectivity.parquet`) — это производный материал от данных FlyWire под
CC BY-NC 4.0. В git идут только сводки без идентификаторов:
`results/mb_subcircuit/type_counts.tsv`, `subcircuit_stats.json`, `config.json`,
`compartment_map.tsv`, `checksums.txt`.

## 4. Что из выходов прогонов попадает в репозиторий

Идёт в git — мелкие сводки, служащие фикстурами лестницы валидации:

- `results/v0_sugar/rate.csv`, `rate_std.csv`, `mn9.json` — результат ступени V0;
- `results/huang_reference/*.txt` — вычисленный эталон H1b, разбор дизайна архивов,
  контрольные суммы;
- `results/mb_subcircuit/*` — счётчики типов, карта компартментов, конфиг подсхемы
  и его хэш, контрольные суммы разметки (см. раздел 3).

Не идёт — сырые спайки (`*.parquet`) и логи: они воспроизводятся из кода и конфига,
велики, и по нашему прочтению CC BY-NC 4.0 наследуют ограничение NC от данных
FlyWire как производный материал. Объём понятия Adapted Material для выходов модели
не подтверждён юристом — открытый вопрос записки о лицензиях.
